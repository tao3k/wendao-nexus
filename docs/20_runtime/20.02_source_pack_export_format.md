# 20.02 SourcePack Export Format

SourcePack Export Format v1 is the handoff contract for upstream tools that
prepare evidence for Wendao Nexus. The exporter can be a customer script, a
private ETL job, a research prototype, or a future optional CocoIndex exporter,
but the output must be a Nexus-owned source pack.

This format is parser-free. Nexus does not parse PDFs, HTML, Word files, Docling
objects, or live APIs here. Upstream systems must already provide normalized
document records with source identity, canonical URI, provenance-bearing
metadata, authority, license, and evidence kind.

## Directory Shape

The required v1 handoff shape is:

```text
<pack>/
  source_pack.toml
  documents.jsonl
```

Additional local payload files are allowed when they are listed by a source
`fixture_path`, such as `guideline.jsonl`. Repository-owned business fixtures
also include `expected_search.snap`, `expected_open.snap`, `expected_status.snap`,
and `expected_compare.snap` for conformance tests. Those `.snap` files are
goldens, not customer handoff requirements and not runtime storage.

## Manifest Contract

`source_pack.toml` uses manifest schema version `1`:

```toml
[source_pack]
id = "customer-private-sop-pack"
version = "2026.05-fixture"
schema_version = 1
domain = "customer_private"
display_name = "Customer Private SOP Pack"
producer = "customer-exporter"
authority_level = "CustomerInternal"
license = "Customer Confidential"

[[sources]]
source_id = "customer-sop-demo"
kind = "CustomerPrivateCorpus"
fixture_path = "documents.jsonl"
display_name = "Customer SOP Export"
license = "Customer Confidential"
authority_level = "CustomerInternal"
enabled = true

[[source_profiles]]
source_id = "customer-sop-demo"
domain = "customer_private"
authority_level = "CustomerInternal"
expected_identifiers = ["customer_doc_id"]
expected_evidence_kinds = ["customer_internal_note"]
license_policy = "Customer Confidential"
requires_canonical_uri = true
requires_revision_or_version = true
requires_license = true
```

`fixture_path` is resolved relative to the manifest. Disabled sources stay
visible in source catalog records but do not become executable local corpus
connectors.

`[[source_profiles]]` is optional. When omitted, Nexus derives a default profile
from the source and pack domain, authority, and license. When present, each
profile must reference exactly one declared `source_id`; unknown source ids,
duplicate profiles, and whitespace-padded `license_policy` values are rejected.
Profiles are used by the Rust basic authority judge to check required
identifiers, expected evidence kinds, staleness, license presence, canonical
URI presence, and revision/version requirements.

## Document Records

`documents.jsonl` is newline-delimited normalized evidence. Each record should
carry the fields needed by Nexus contracts and Wendao-side parsers:

```json
{
  "external_id": "customer/sop/clinical-trial-intake",
  "canonical_uri": "customer://acme/sop/clinical-trial-intake",
  "title": "Clinical Trial Intake SOP",
  "body": "The QA reviewer must approve the intake packet before enrollment.",
  "source_updated_at": "2026-04-10T00:00:00Z",
  "metadata": {
    "evidence_kind": "customer_internal_note",
    "tenant_id": "acme-bio",
    "department": "clinical-operations",
    "license_name": "Customer Confidential",
    "license_usage_policy": "internal_only"
  }
}
```

Domain-specific values such as `doi`, `pmid`, `jurisdiction`, `article`,
`effective_at`, `region`, `crop`, and `price_date` remain metadata in v1. This
keeps the export format stable while legal, medical, agriculture, and customer
fixtures prove which fields deserve a later strongly typed domain schema.

## Validation

`validate_source_pack_export(path)` accepts either the export directory or a
manifest file. Directory input expects `source_pack.toml`; JSON manifests should
be passed as explicit manifest file paths. It checks:

- manifest syntax and schema version;
- non-empty pack identity, version, source ids, license, and display names;
- at least one enabled source;
- unique source ids;
- every declared `fixture_path` points at a readable file;
- enabled sources can be loaded by the deterministic local corpus connector.

The validator returns a report with pack id, domain, source counts, enabled
connector count, effective authority profiles, and declared fixture paths.
Effective profiles include explicitly declared profiles and default profiles
derived from pack/source domain, authority, and license. This gives downstream
exporters a cheap way to verify that every source will enter the Rust basic
authority judge with a concrete profile before any runtime ingest happens. It
does not start jobs, write stores, open live clients, call Wendao, or create a
search backend.

## Boundary

The export format is the only contract a future optional bridge should emit.
CocoIndex or any other upstream tool may prepare data, but it must hand off this
SourcePack v1 shape so Nexus keeps ownership of evidence kind, authority,
license, provenance metadata, artifact replay, and Arrow Flight output.
