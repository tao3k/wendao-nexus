# 10.02 Flight Protocol

`wendao-nexus-flight` is the public contract surface that the Wendao-side server
can mount. It carries protocol contracts, not server ownership.

## Routes

The canonical routes are:

```text
/knowledge/external/search
/knowledge/external/open
/knowledge/external/sync
/knowledge/external/status
/knowledge/external/compare
```

Route strings are stable wire identity. Command encoding should use these route
strings instead of serde variant names so Wendao can route requests without
depending on Rust enum layout.

## Command Envelope

The typed command layer covers:

- `Search` for evidence search requests;
- `Open` for opening a source document with optional sections and provenance;
- `Sync` for source-level sync jobs;
- `Status` for source or job status queries;
- `Compare` for claim/evidence conflict checks.

Commands can be encoded to JSON or embedded in Flight descriptors. Unsupported
routes and unsupported descriptor types should fail explicitly.

## Batch Contracts

The batch helpers expose typed row builders for:

- search results;
- opened documents and sections;
- sync results;
- status rows;
- compare evidence rows.

Timestamp fields use nanosecond UTC Arrow timestamps. Batch builders should keep
schema order stable because downstream clients may consume by column name and by
contracted table shape.

They also include conversion helpers from core evidence contracts:

- `search_rows_from_response` maps `ExternalKnowledgeSearchResponse` records
  into search rows;
- `open_rows_from_document` maps a normalized `ExternalKnowledgeDocument` into
  document or section rows with optional provenance JSON.

## Provider Contract

`NexusFlightBatchProvider` is a thin adapter for the Wendao-side server. It
accepts a decoded `NexusFlightCommand` or `FlightDescriptor`, dispatches it to a
`NexusFlightCommandHandler`, and converts returned rows into the route-specific
`RecordBatch`.

The handler implementation owns storage, query, connector, and runtime policy.
The provider owns only command dispatch and Arrow batch construction.

`wendao-nexus` provides `LocalMirrorFlightHandler` as the first facade handler.
It serves search, open, status, and compare from a local mirror store and
checkpoint registry. Sync remains a Wendao-side runtime concern because live
connector ownership, auth, and scheduling policy belong outside the protocol
crate.

## Integration Rule

This repository should not add a `wendao-nexus-server` crate. Wendao already
owns the server surface. Nexus should provide the protocol, command, schema,
batch, provider, runtime, and connector pieces that the Wendao-side server
mounts.
