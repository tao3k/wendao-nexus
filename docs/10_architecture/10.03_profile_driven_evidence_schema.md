# 10.03 Profile-Driven Evidence Schema

Nexus should not encode every domain-specific external field in Rust. Rust owns
the stable evidence boundary, source profile validation, canonical projection,
and deterministic policy evaluation. Source-specific field semantics belong to
SourceProfile manifests, dynamic evidence attributes, and downstream evidence
algorithms.

## Current Risk

The v0 contracts intentionally named the first business fields needed by
medical, legal, agriculture, and customer-private fixtures. That made early
source packs concrete and testable, but it must not become the long-term
extension mechanism.

The risk pattern is:

```text
new industry or source
  -> new Rust metadata constants
  -> new Rust getters
  -> new judge branches
  -> new Arrow columns
```

That path makes Nexus a growing catalog of external database schemas. Real
sources are too varied for that.

## Stable Core

Rust should keep only the evidence skeleton stable:

```text
source_id
external_id
canonical_uri
source_kind
authority_level
fetched_at
content_hash
provenance
license
evidence_kind
published_at
source_updated_at
```

Those fields are contract invariants. They are needed for provenance,
deduplication, trust filtering, evidence display, and Arrow Flight handoff.

## Dynamic Attributes

All source-specific fields should move toward dynamic evidence attributes:

```text
medical.pmid
medical.mesh_terms
legal.statute
legal.article
agriculture.crop
agriculture.price_date
customer.department
```

The next schema shape should be profile-driven:

```text
FieldKey(namespace, name)
EvidenceValue(string | number | bool | timestamp | string_list | json)
EvidenceAttribute(value, confidence, source_path)
EvidenceAttributes(values)
```

The current `SourceMetadata.extra` map is a compatibility bridge. It should be
preserved for existing fixtures, but new external fields should be described in
profiles and carried through attributes rather than added as Rust constants.

The core crate now exposes the first contract pieces for this migration:

```text
FieldKey
EvidenceValue
EvidenceAttribute
EvidenceAttributes
EvidenceFieldType
FieldDescriptor
CanonicalEvidenceSlot
```

These types are not wired into runtime normalization or Flight schemas yet.
They are the stable target shape for the next migration slice.

`SourceAuthorityProfile` can already carry `fields: Vec<FieldDescriptor>`.
Existing profiles default that list to empty, so current SourcePack manifests
remain compatible while new profiles can start declaring field semantics.

## SourceProfile Direction

Source profiles should declare field semantics:

```text
field namespace
field name
field type
aliases
required flag
identifier role
canonical slot mapping
freshness policy
license policy
authority policy
```

The Rust judge should read profile policy instead of hard-coding that a
particular domain needs PMID, DOI, jurisdiction, statute, article, crop, or
price date. Domain defaults may remain as convenience presets, but the profile
must be the source of truth.

## Canonical Projection

Rust should project dynamic attributes into a small canonical view:

```text
title
identifiers
published_at
updated_at
license
jurisdiction
evidence_kind
domain
```

The projection exists so policy checks, Flight rows, and agent evidence
boundaries can stay stable while source-specific fields remain dynamic.

## Flight Direction

Current search schemas keep v1 compatibility columns such as `doi`, `pmid`, and
`jurisdiction`. Future extension should not add one Arrow column per industry
field. The next compatible extension should add:

```text
attributes_json
warnings_json
profile_id
profile_version
```

Later, an optimized deployment can materialize domain-specific views or Arrow
map/struct columns outside the core Nexus contract.

## Governance Rule

The current `SOURCE_METADATA_*` constants are frozen as a v0 compatibility
surface. Adding a new source-specific field requires one of these first:

- a SourceProfile field descriptor;
- a dynamic attribute projection rule;
- a documented canonical slot that is broadly useful across domains.

This keeps Nexus from becoming a Rust enum of every external database shape.
