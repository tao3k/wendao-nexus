# 10.01 Nexus Boundary

Wendao Nexus is the external knowledge source ingestion and trust registry
layer for Wendao. It is intentionally independent from `xiuxian-*` crates and
does not own a standalone server in this repository.

## Responsibility

Nexus owns:

- external source identity, source kind, capability, cursor, and checkpoint
  contracts;
- normalized external document, section, citation, license, and provenance
  contracts;
- extracted document resource contracts compatible with Wendao
  attachment/document extraction output;
- connector traits and source adapter crates;
- sync runtime traits for jobs, checkpoints, and content hash dedup;
- public Arrow Flight routes, schemas, command envelopes, and batch helpers.

Nexus does not own:

- `xiuxian-db-store`, `xiuxian-vector`, `xiuxian-wendao-core`, or
  `xiuxian-wendao-runtime` dependencies;
- the Wendao server process;
- Docling worker orchestration, attachment parsing, or agent scheduling;
- final LLM answer authority;
- customer-specific adjudication or persona policy.

## Mounting Model

The server boundary points toward Wendao:

```text
wendao-nexus-core / flight / runtime / connectors
  -> mounted or linked by the Wendao-side server
  -> parsed by Wendao attachment/Docling pipelines when needed
  -> exposed through Wendao Flight service and agent tools
```

This keeps the dependency direction legal. Nexus can be used by Wendao without
knowing about Wendao internals. If a Rust-level adapter is needed, it belongs on
the Wendao or `xiuxian-artisan-workshop` side.

## Crate Map

```text
crates/wendao-nexus
crates/wendao-nexus-core
crates/wendao-nexus-flight
crates/wendao-nexus-runtime
crates/wendao-nexus-connectors
```

`wendao-nexus` is the facade adapter crate for mountable composition pieces.
`wendao-nexus-core` is the stable domain model. `wendao-nexus-flight` is the
public protocol layer. `wendao-nexus-runtime` is sync orchestration and registry
facades. `wendao-nexus-connectors` is source-specific adapter code.

## Authority Boundary

Nexus returns evidence, provenance, and source metadata. LLM output remains
subordinate to governed sources. Authority-sensitive flows should return
evidence records and provenance bundles rather than prose-only answers.
