# 90.01 Validation and Governance

This repo validates Rust correctness and documentation shape separately.

## Rust Validation

Run the workspace checks through the repo environment:

```shell
direnv exec . cargo fmt --all -- --check
direnv exec . cargo fetch --locked
direnv exec . cargo test --workspace --all-targets --all-features --locked
direnv exec . cargo test --workspace
direnv exec . cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
direnv exec . cargo test --workspace rust_project_harness_gate --locked -- --nocapture
direnv exec . git diff --check
```

GitHub CI is adapted from `rust-lang-project-harness/.github` into
`.github/workflows/ci.yml`. It runs the locked Rust workspace tests across
Linux, macOS, and Windows, while keeping formatting, strict Clippy, explicit
harness gate, and whitespace checks on Ubuntu.

The workspace tests include the Nexus phase guard. That guard keeps default
builds free of production live source clients, parser dependencies,
DuckDB/Tantivy/Lance-style storage or search engines, cache backends,
CocoIndex, and public local knowledge-store ownership. The only allowed live
client dependency is optional `reqwest` in `wendao-nexus-connectors`, gated by
the `live-probe` feature and env-gated tests that skip unless
`WENDAO_NEXUS_RUN_LIVE_PROBE=1`.
They also include the facade conformance suite, which fixes the pre-adapter
contract for Flight routes, command envelopes, Arrow schemas and batches,
directory-first source packs, fixture command handling, and artifact replay.
`NexusFixtureHarness` is covered there as the public serverless harness for
adapter-facing tests.

## Documentation Topology

Johnny.Decimal documentation follows `docs/topology.toml`:

- category meaning is declared in the manifest;
- note files use `AC.ID_semantic_name.md`;
- parent directories begin with the same category prefix as the note;
- new categories require a reviewed manifest change;
- LLM-authored moves, creates, and renames remain reviewable proposals until
  deterministic lint and audit checks pass.

The governing policy template is the path-first Johnny.Decimal authoring flow
from `wendao-episteme/policies/johnny_decimal`.

## Wendao Audit

When the Wendao CLI is available, run:

```shell
wendao audit --template johnny-decimal
wendao lint markdown docs
wendao audit --load wendao-episteme docs
```

If the CLI is not available in the current repo shell, record that as a
validation gap instead of pretending the audit passed. Do not bypass the
post-write lint and audit expectation by silently changing document coordinates
or category meanings.
